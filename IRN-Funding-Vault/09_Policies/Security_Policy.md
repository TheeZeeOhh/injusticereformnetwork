# Security Policy & Operational Security Protocol

All organizer communications, community records, and financial ledgers must be encrypted at rest, encrypted in transit, and ephemeral by default to neutralize dragnet surveillance, subpoena threats, and state-level digital counter-insurgency.

Protective infrastructure is built right the first time, locked in tight, and maintained with continuous vigilance so our movement remains impenetrable.

## 2. Soul Walk P2P Mesh Network Security Architecture (Zero-Trust Offline Sync)

- **Zero-Trust P2P Mesh Topography**: Soul Walk operates as a decentralized, offline-first peer-to-peer mesh network designed to maintain data sync during complete internet blackouts, telecom shutdowns, or targeted network censorship. Every node on the mesh operates under zero-trust assumptions—peers must continuously authenticate and verify state transitions using cryptographic signatures.
- **Merkle-Search Trie Memory Engine**: Network state and localized data are organized into an immutable Merkle-Search Trie data structure. Each trie node encapsulates a key identifier, high-dimensional vector embeddings, a microsecond-precision timestamp, and a parent node hash. Navigation follows lexicographical trie paths, ensuring deterministic state verification across all mesh participants.
- **SAPL v1.1 Watermarked Cryptographic Seals**: Every Merkle Trie node hash is computed using SHA-256 with embedded Sanctuary Autonomous Public License (SAPL) v1.1 legal text watermarking. This watermark cryptographically and legally binds any external AI model or web scraper ingesting mesh data to open-source their model weights under SAPL terms, turning adversary surveillance into legal exposure.
- **LWW-CRDT Conflict Resolution Protocol**: Node updates use a Last-Write-Wins Conflict-Free Replicated Data Type (LWW-CRDT) algorithm. When concurrent state updates occur across disconnected mesh segments, nodes resolve collisions deterministically by comparing cryptographically signed timestamps, guaranteeing eventual consistency across all nodes upon mesh reconnection without central server intervention.
- **Local Embedding Security & Ollama Isolation**: Vectorization for semantic search across the mesh runs strictly on local edge hardware via isolated Ollama endpoints (`http://localhost:11434`) using `nomic-embed-text`. Raw data and high-dimensional embeddings never leave the local node, completely eliminating cloud API leakage and protecting against vector inversion attacks.

## 3. Mandatory Device-Level & Storage Encryption Protocols (LUKS/FileVault, Hardware Security)

- **Full-Disk Encryption (FDE) Baseline**: All organizer hardware—laptops, desktops, servers, and mobile devices—must run mandatory full-disk encryption prior to provisioning. Linux systems enforce LUKS2 with Argon2id key derivation and 256-bit AES-XTS; macOS devices enforce FileVault 2 with Secure Enclave hardware backing. Unencrypted boot drives are strictly prohibited across the organization.
- **Hardware Security Keys & YubiKey Integration**: Authentication across all accounts, SSH sessions, Git commits, and secret vaults requires physical FIDO2/WebAuthn hardware security keys (YubiKey 5 Series). Static passwords, SMS 2FA, and authenticator apps are banned for core infrastructure access. Hardware keys must be stored in tamper-evident pouches when not in active use.
- **Encrypted Storage Partitioning & VeraCrypt Outer/Inner Vaults**: High-sensitivity operational archives and funding ledgers must be stored inside hidden VeraCrypt containers using cascaded encryption algorithms (AES-Twofish-Serpent). Organizers must configure plausible deniability with decoy outer volumes and hidden inner volumes to protect critical assets during physical search or coerced unlock scenarios.
- **Mobile Device Hardening & Operating System Baseline**: Mobile devices utilized for field operations must run open-source, hardened operating systems (such as GrapheneOS on Pixel hardware) with memory tagging enabled, pinned cryptographic key sets, disabled remote management profiles, and background telemetry completely severed.
- **Ephemeral Key Exchange & Forward Secrecy**: All real-time messaging across organizers must utilize end-to-end encrypted protocols (Signal Protocol / Double Ratchet Algorithm) with per-session key rotation every 24 hours and self-destructing timer defaults set to 1 hour or less for operational field comms.

## 4. OPSEC, Counter-Surveillance & Digital Redlining Protections

- **Digital Redlining Proxy Countermeasures**: In accordance with Operation Glass House audit findings, organizers are strictly forbidden from inputting community geographic data (ZIP codes, neighborhood names, local school districts) or credit proxies into unverified digital platforms. State risk algorithms rely on these proxies to enforce algorithmic discrimination and targeted police deployments.
- **Automated Metadata Scrubbing Pipelines**: All documents, PDFs, images, and audio files must pass through automated metadata cleaning pipelines (`exiftool`, `pdf-redact-tools`) before external distribution or mesh syncing. Camera EXIF data, GPS coordinates, device serial numbers, author metadata, and software revision histories must be scrubbed cleanly.
- **Network Anonymization via Multi-Hop VPNs & Tor**: Direct connection to public IP addresses is forbidden. All external network requests must route through multi-hop WireGuard VPN tunnels or the Tor onion network. Organizers must utilize Mullvad Browser or Tor Browser with strict JavaScript restrictions enabled for web research.
- **Compartmentalization & Burner Persona Protocol**: Organizers must maintain absolute separation between personal digital footprints and IRN operational activities. Operations must utilize isolated virtual machines (Qubes OS or Whonix), pseudonymous single-use email accounts over encrypted providers (ProtonMail / SimpleLogin aliases), and non-attributable infrastructure.
- **Anti-Surveillance & Stingray Mitigation**: During field mobilizations, organizers must deploy physical Faraday bags for mobile devices, utilize IMSI-catcher/Stingray detection tools (such as SnoopSnitch and RF spectrum analyzers), and maintain devices in full airplane mode with Wi-Fi/Bluetooth/NFC hardware kill-switches engaged.

## 5. Physical Security & Air-Gapped Organizers Procedures

- **Air-Gapped Cold Vault Operations**: Root cryptographic keys, multi-signature treasury seeds, and master identity registries must reside exclusively on air-gapped hardware. Air-gapped workstations must have wireless cards, Bluetooth modules, and webcams physically removed or desoldered. Data transfer to/from air-gapped nodes is restricted to single-use, cryptographically verified USB drives.
- **Physical Device Tamper Seals**: All organizers' laptops and hardware vaults must be sealed with unique, serialized tamper-evident tape and customized glitter-nail-polish anti-tamper patterns over chassis seams and USB ports. Organizers must perform photographic checksum verification of tamper patterns prior to every system boot.
- **Secure Physical Workspace Rules**: Workspaces handling IRN operational data must enforce strict clear-desk policies, 3M 60-degree polarized privacy screen filters on all displays, white-noise acoustic masking devices to prevent laser microphone eavesdropping, and biometric/mechanical safe storage for devices when unattended.
- **Field Operations Safety Protocol**: Organizers deploying into field environments must carry stripped devices containing zero historical data, zero saved passwords, and zero personal contact lists. Devices must be configured with single-tap duress wipes and physical tether switches that trigger instant lockouts if separated from the organizer.
- **Chain of Custody & Device Lifecycle Disposal**: Storage drives and hardware reaching end-of-life or suspecting physical compromise must undergo certified physical destruction. Disposal procedures require multi-pass degaussing followed by physical shredding or thermal destruction of memory chips down to sub-millimeter particles.

Receiving a verified panic beacon signed by an emergency key causes all connected peer nodes to instantly sever connections to the compromised node ID, prune its Merkle Trie sub-branches, and seal local vector databases against external sync requests.

Following an incident, organizers conduct forensic root-cause analysis, execute key re-anchoring rituals, and redeploy upgraded defense nodes—ensuring our movement bounces back stronger, wiser, and fully locked in.
